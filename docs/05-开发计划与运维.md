**阶段验收脚本**（保存为 `scripts/smoke-test.ps1`，逐个跑通）：

```powershell
$ErrorActionPreference = 'Stop'
$base = 'http://127.0.0.1:8787'

# 中文 JSON 必须转 UTF-8 字节，否则 PowerShell 5.1 会按 ASCII 发送（见 §5.7）
function PostJson($url, $obj) {
    $json = $obj | ConvertTo-Json -Depth 6
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
    Invoke-RestMethod -Uri $url -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes
}
function PatchJson($url, $obj) {
    $json = $obj | ConvertTo-Json -Depth 6
    $bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
    Invoke-RestMethod -Uri $url -Method Patch -ContentType 'application/json; charset=utf-8' -Body $bytes
}

Write-Host "`n=== 1. 健康检查 ===" -ForegroundColor Cyan
Invoke-RestMethod "$base/api/health" | ConvertTo-Json -Depth 4

Write-Host "`n=== 2. 建一条待办 ===" -ForegroundColor Cyan
$todo = PostJson "$base/api/records?type=todo" @{
    title = '把《算法导论》第3章课后题做完'
    content = '重点做 3-2 和 3-5'
    tags = @('算法', '课后题')
    dueDate = '2026-10-10'
    priority = 'high'
}
$todo | ConvertTo-Json -Depth 4
$todoId = $todo.id

Write-Host "`n=== 3. 建一条碎片知识（缺 subject，应返回 400） ===" -ForegroundColor Cyan
try {
    PostJson "$base/api/records?type=knowledge" @{ title = '测试'; }
    Write-Host "✗ 未报错——校验有 bug" -ForegroundColor Red
} catch {
    $r = $_.ErrorDetails.Message | ConvertFrom-Json
    if ($r.error.code -eq 'invalid_subject') { Write-Host "✓ 正确返回 invalid_subject" -ForegroundColor Green }
    else { Write-Host "✗ 错误码不对：$($r.error.code)" -ForegroundColor Red }
}

Write-Host "`n=== 4. 建一条碎片知识（正常） ===" -ForegroundColor Cyan
$k = PostJson "$base/api/records?type=knowledge" @{
    title = '矩阵乘法的几何意义'
    content = 'AB 表示先做 B 的变换，再做 A 的变换'
    subject = '数学/线性代数'
    tags = @('线性代数')
}
Write-Host "✓ id=$($k.id) subject=$($k.subject)"

Write-Host "`n=== 5. 标记待办完成（检查 doneAt 联动） ===" -ForegroundColor Cyan
$done = PatchJson "$base/api/records/$todoId" @{ status = 'done' }
if ($done.doneAt) { Write-Host "✓ doneAt=$($done.doneAt)" -ForegroundColor Green }
else { Write-Host "✗ doneAt 未写入" -ForegroundColor Red }

Write-Host "`n=== 6. 回退为 open（检查 doneAt 清空） ===" -ForegroundColor Cyan
$open = PatchJson "$base/api/records/$todoId" @{ status = 'open' }
if (-not $open.doneAt) { Write-Host "✓ doneAt 已清空" -ForegroundColor Green }
else { Write-Host "✗ doneAt 未清空：$($open.doneAt)" -ForegroundColor Red }

Write-Host "`n=== 7. 追加笔记 ===" -ForegroundColor Cyan
$withNote = PostJson "$base/api/records/$todoId/notes" @{ content = '第一条笔记' }
Write-Host "✓ 笔记数=$($withNote.notes.Count) noteId=$($withNote.notes[0].id)"

Write-Host "`n=== 8. 统计总览（检查完成率口径） ===" -ForegroundColor Cyan
$s = Invoke-RestMethod "$base/api/stats/overview"
$s | ConvertTo-Json -Depth 4
Write-Host "完成率分母=$($s.todoCompletion.denominator)（应为 done+open，不含 cancelled）"

Write-Host "`n=== 9. 心愿单 ===" -ForegroundColor Cyan
$w1 = PostJson "$base/api/wishlist" @{ name = 'HHKB 键盘'; amountCents = 238800 }
$w2 = PostJson "$base/api/wishlist" @{ name = '《算法导论》'; amountCents = 12800 }
PatchJson "$base/api/wishlist/$($w2.item.id)" @{ purchased = $true } | Out-Null
$list = Invoke-RestMethod "$base/api/wishlist"
$list.summary | ConvertTo-Json
$expect = $list.summary.totalWishCents -eq ($list.summary.spentCents + $list.summary.remainingCents)
if ($expect) { Write-Host "✓ 恒等式 总=已花+还差 成立" -ForegroundColor Green }
else { Write-Host "✗ 恒等式不成立" -ForegroundColor Red }

Write-Host "`n=== 10. 金额传小数（应返回 400） ===" -ForegroundColor Cyan
try {
    PostJson "$base/api/wishlist" @{ name = '测试'; amountCents = 19.99 }
    Write-Host "✗ 未报错" -ForegroundColor Red
} catch {
    $r = $_.ErrorDetails.Message | ConvertFrom-Json
    Write-Host "✓ $($r.error.code)：$($r.error.message)" -ForegroundColor Green
}

Write-Host "`n=== 11. 随机抽取（连续 5 次应不重复） ===" -ForegroundColor Cyan
$seen = @()
for ($i = 0; $i -lt 5; $i++) {
    $ex = if ($seen.Count) { '&exclude=' + ($seen -join ',') } else { '' }
    $r = Invoke-RestMethod "$base/api/stats/random?type=knowledge$ex"
    if (-not $r.record) { Write-Host "（池中仅 $($r.poolSize) 条，跳过）"; break }
    $seen += $r.record.id
    Write-Host "  第 $($i+1) 次：$($r.record.title)"
}
$uniq = ($seen | Select-Object -Unique).Count
if ($uniq -eq $seen.Count) { Write-Host "✓ 无重复" -ForegroundColor Green }
else { Write-Host "✗ 出现重复" -ForegroundColor Red }

Write-Host "`n=== 12. 查询筛选 ===" -ForegroundColor Cyan
$q = Invoke-RestMethod "$base/api/records?type=knowledge&subject=数学"
Write-Host "✓ subject=数学 命中 $($q.pagination.total) 条（含子学科）"
$q2 = Invoke-RestMethod "$base/api/records?type=todo&tags=算法"
Write-Host "✓ tags=算法 命中 $($q2.pagination.total) 条"

Write-Host "`n=== 13. 清理测试数据 ===" -ForegroundColor Cyan
Invoke-RestMethod -Uri "$base/api/records/$todoId" -Method Delete | Out-Null
Invoke-RestMethod -Uri "$base/api/records/$($k.id)" -Method Delete | Out-Null
Invoke-RestMethod -Uri "$base/api/wishlist/$($w1.item.id)" -Method Delete | Out-Null
Invoke-RestMethod -Uri "$base/api/wishlist/$($w2.item.id)" -Method Delete | Out-Null
Write-Host "✓ 已清理" -ForegroundColor Green

Write-Host "`n全部检查完成。请人工核对上面标红的项。" -ForegroundColor Yellow
```

## 5.2 依赖获取清单

共 **4 个**第三方文件需手动放置（3 个前端 vendor + 1 个后端 jar）。全部本地引用，运行时不访问外网。

| 文件 | 放置位置 | 用途 | 大小 | 来源 |
|---|---|---|---|---|
| `gson-2.11.0.jar` | `server/lib/` | JSON 序列化 | ~283 KB | Maven Central：`https://repo1.maven.org/maven2/com/google/code/gson/gson/2.11.0/gson-2.11.0.jar` |
| `chart.umd.min.js` | `web/vendor/` | 环形图 | ~205 KB | `https://cdn.jsdelivr.net/npm/chart.js@4.4.4/dist/chart.umd.min.js` |
| `marked.min.js` | `web/vendor/` | Markdown 解析 | ~40 KB | `https://cdn.jsdelivr.net/npm/marked@14.1.2/marked.min.js` |
| `purify.min.js` | `web/vendor/` | **HTML 净化（XSS 防护，必需）** | ~22 KB | `https://cdn.jsdelivr.net/npm/dompurify@3.1.6/dist/purify.min.js` |

**PowerShell 批量下载**（需联网）：

```powershell
$ErrorActionPreference = 'Stop'
$root = 'D:\Documents\qwen-agent\GGibrnReLK\Pouch'
New-Item -ItemType Directory -Force -Path "$root\server\lib", "$root\web\vendor" | Out-Null

$files = @(
    @{ url='https://repo1.maven.org/maven2/com/google/code/gson/gson/2.11.0/gson-2.11.0.jar';  out="$root\server\lib\gson-2.11.0.jar" },
    @{ url='https://cdn.jsdelivr.net/npm/chart.js@4.4.4/dist/chart.umd.min.js';               out="$root\web\vendor\chart.umd.min.js" },
    @{ url='https://cdn.jsdelivr.net/npm/marked@14.1.2/marked.min.js';                        out="$root\web\vendor\marked.min.js" },
    @{ url='https://cdn.jsdelivr.net/npm/dompurify@3.1.6/dist/purify.min.js';                 out="$root\web\vendor\purify.min.js" }
)

foreach ($f in $files) {
    Write-Host "→ 下载 $($f.url)"
    Invoke-WebRequest -Uri $f.url -OutFile $f.out -UseBasicParsing
    $size = (Get-Item $f.out).Length
    Write-Host "  ✓ $([math]::Round($size/1KB,1)) KB → $($f.out)"
    # 极小的文件通常意味着下载到的是错误页面而非真实资源
    if ($size -lt 5KB) { Write-Warning "文件过小，可能下载失败，请检查内容" }
}
Write-Host "`n完成。请确认上述 4 个文件都已就位。"
```

**下载后必须验证**：

1. `gson-2.11.0.jar` 能被 `javac -cp "server/lib/*"` 识别（编译不报 `package com.google.gson does not exist`）
2. 三个 `.js` 文件首行是 JS 代码而非 HTML（若 CDN 返回 404 页面，文件会是 `<!DOCTYPE html>...`）

> **版本号说明**：上述版本是文档撰写时的稳定版。若下载更新版本，注意两个已知的破坏性变更点：
> - Chart.js 3.x → 4.x 改了配置结构（本文档按 4.x 写）
> - marked 5.x → 12.x 移除了 `marked.setOptions` 的部分选项，且默认不再转义 HTML（因此 DOMPurify 变得更必要）
>
> 换版本前先读该库的迁移指南。

**HTML 中的引入顺序**（有依赖关系，顺序不能错）：

```html
<!-- vendor：普通 script，同步加载，必须在 module 之前 -->
<script src="/vendor/purify.min.js"></script>
<script src="/vendor/marked.min.js"></script>
<script src="/vendor/chart.umd.min.js"></script>

<!-- 业务代码：module 是 defer 语义，一定在上面三个之后执行 -->
<script type="module" src="/js/detail.js"></script>
```

`marked`、`DOMPurify`、`Chart` 都挂在 `window` 上作为全局变量。在 ES module 中直接引用全局变量是可行的（module 能访问全局作用域），但**建议在模块顶部显式取出并检查存在性**，避免 vendor 文件加载失败时报出难以理解的 `Chart is not defined`：

```js
const { marked, DOMPurify } = window;
if (!marked || !DOMPurify) {
  console.error('依赖未加载：请检查 web/vendor/ 下的 marked.min.js 与 purify.min.js');
}
```

## 5.3 启动与停止

### 日常使用

```powershell
# 进入仓库根目录
cd D:\Documents\qwen-agent\GGibrnReLK\Pouch

# 启动（会自动检测源码变更并重新编译）
.\server\start.ps1

# 换端口
.\server\start.ps1 -Port 9000

# 指定其他数据目录（例如把数据放到 OneDrive 同步盘）
.\server\start.ps1 -Data "D:\MyNotes\pouch-data"
```

启动成功后浏览器访问 `http://127.0.0.1:8787`。

### 停止

控制台窗口按 `Ctrl+C`。`PouchServer` 注册了 shutdown hook（02 §2.8），会等待进行中的写入完成（最多 2 秒）后退出。

**直接关闭控制台窗口也可以**——Windows 会发送关闭信号触发同一个 hook。但**不要用任务管理器强制结束进程**，那会跳过 hook，可能中断正在进行的写入（此时依赖 01 §1.7.2 的原子写保证数据不损坏，但备份可能不完整）。

### 端口被占用

```powershell
# 查看谁占用了 8787
netstat -ano | findstr :8787

# 输出示例：
#   TCP    127.0.0.1:8787    0.0.0.0:0    LISTENING    12345
#                                                          ↑ PID

# 查看该 PID 是什么进程
Get-Process -Id 12345
```

若是上次没关干净的 Pouch 实例，`Stop-Process -Id 12345` 后重启；若是别的服务，用 `-Port` 换一个。

### 桌面快捷方式（可选）

创建 `启动Pouch.bat` 放在桌面：

```bat
@echo off
chcp 65001 >nul
cd /d D:\Documents\qwen-agent\GGibrnReLK\Pouch
powershell -NoProfile -ExecutionPolicy Bypass -File .\server\start.ps1
```

> **关于 `-ExecutionPolicy Bypass`**：若你的机器上 PowerShell 执行策略阻止脚本运行（报 `UnauthorizedAccess`），上面这行能绕过。但**绕过执行策略会降低系统安全性**，更好的做法是一次性为当前用户放开：
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```
>
> 这只影响你自己的账户，允许运行本地脚本（从网上下载的脚本仍需显式解除锁定），是 Windows 开发机的常规配置。改完之后 `.bat` 里就不需要 `-ExecutionPolicy Bypass` 了。

## 5.4 数据备份策略

系统已有**自动备份**（每次写入前，保留最近 50 份/文件，见 01 §1.7.3）。但自动备份防的是"文件损坏"，防不了：

- 硬盘故障
- 误删整个 `data/` 目录
- 勒索软件

因此需要**独立的第二层备份**。

### 方案 A：Git 版本管理（推荐）

数据是纯文本 JSON，天然适合 Git。

```powershell
cd D:\Documents\qwen-agent\GGibrnReLK\Pouch
git init
```

`.gitignore`：

```gitignore
# 编译产物
server/out/

# 自动备份与损坏文件隔离（这些是运行时产物，不入版本库）
data/.backup/
*.corrupt
*.corrupt-duplicate
.tmp/

# 系统文件
Thumbs.db
.DS_Store

# 第三方依赖体积大且可重新下载，按需选择是否入库
# 若希望克隆后开箱即用，注释掉下面三行
server/lib/*.jar
web/vendor/*.js
```

日常提交：

```powershell
git add data/
git commit -m "data: 2026-10-02 记录更新"
```

**优点**：每条记录的变更历史可追溯（`git log -p data/knowledge.json`），误改可精确回滚。
**代价**：`data/` 会随记录增长，Git 仓库变大。单用户学习记录场景下，一年也就几十 MB，可接受。

> **不要把 `data/.backup/` 纳入 Git**。它是运行时产物，每次写入都变，会让每次 commit 都带上 50 个二进制式变更，仓库迅速膨胀且失去可读性。

### 方案 B：定期复制到同步盘

```powershell
# 保存为 scripts\backup.ps1，用任务计划程序每天执行
$src  = 'D:\Documents\qwen-agent\GGibrnReLK\Pouch\data'
$dest = "$env:USERPROFILE\OneDrive\PouchBackup\$(Get-Date -Format 'yyyy-MM-dd')"

New-Item -ItemType Directory -Force -Path $dest | Out-Null
# 只复制 5 个数据文件，不复制 .backup/
Get-ChildItem $src -Filter '*.json' | Copy-Item -Destination $dest -Force

# 只保留最近 30 天的备份
Get-ChildItem "$env:USERPROFILE\OneDrive\PouchBackup" -Directory |
    Where-Object { $_.Name -lt (Get-Date).AddDays(-30).ToString('yyyy-MM-dd') } |
    Remove-Item -Recurse -Force
```

> 上面的 `Remove-Item -Recurse -Force` 是**永久删除**。首次运行前请确认路径正确，或先把这行注释掉，人工检查一次生成的目录结构再启用。

### 两方案可叠加

Git 管日常版本历史，同步盘管异地容灾。**不要只用方案 B**——它没有版本粒度，只能恢复到"某天"，无法回答"这条记录是什么时候被改成这样的"。

## 5.5 数据迁移与升级

### 5.5.1 迁移到别的机器

```powershell
# 旧机器：打包数据（不含 .backup）
Compress-Archive -Path D:\...\Pouch\data\*.json -DestinationPath pouch-data.zip

# 新机器：解压到新位置的 data/ 目录，然后启动
.\server\start.ps1 -Data "D:\NewLocation\data"
```

数据结构与机器无关（无绝对路径、无机器标识），直接复制即可。

### 5.5.2 字段结构变更（`version` 的作用）

`version` 字段（01 §1.1.1）当前恒为 `1`。当需要变更字段结构时：

```
1. 写迁移脚本，读入 version=1 的文件，转换结构，写出 version=2
2. JsonStore.load() 中检查 version：
     - == 当前版本 → 正常载入
     - <  当前版本 → 调用迁移链逐级升级（1→2→3），迁移前先备份
     - >  当前版本 → 报错退出（数据由更新版本的程序写入，当前版本无法理解）
3. 迁移在内存中完成后，走正常的原子写落盘
```

**关键规则：迁移必须逐级进行，不能跳级**。若已有 v1→v2 和 v2→v3 两个迁移，遇到 v1 数据要先跑 v1→v2 再跑 v2→v3。跳级迁移在字段经过多轮变更后必然出错。

**当前版本无需实现迁移框架**——`version` 恒为 1，`load()` 只需在 `version > 1` 时报错即可。框架等到第一次真正需要变更结构时再加。

### 5.5.3 新增一个类别

例如想加"读书笔记"类别：

| 步骤 | 改动 |
|---|---|
| 1 | `Category` 枚举加一项 `NOTE("note", "读书笔记", "notes.json")` |
| 2 | 若有专有字段，在 `Record` 加字段，在 `applyTypeSpecific` 加校验分支，在 `clearForeignFields` 加清理 |
| 3 | 在 `allowedStatuses()` 和 `defaultStatus()` 加分支 |
| 4 | 若参与随机回顾，改 `isRandomEligible` |
| 5 | `tokens.css` 加 `--cat-note` 颜色（两套主题各一次） |
| 6 | 其余**全部自动生效**：文件创建、API 端点、列表页导航、筛选栏、详情页、统计计数 |

这正是 ADR-003（统一记录模型）与 03 §3.2（类别元信息走 API 而非前端硬编码）的回报——新增类别是 6 处小改动，而不是复制一整套 CRUD。

## 5.6 故障恢复手册

### 5.6.1 数据文件损坏

**症状**：启动时控制台打印 `[WARN] xxx.json 解析失败，尝试从备份恢复…`；页面顶部出现橙色告警横幅。

**系统已自动处理**：从最新可用备份恢复，损坏文件保留为 `xxx.json.corrupt`。

**人工介入步骤**：

```powershell
cd D:\Documents\qwen-agent\GGibrnReLK\Pouch\data

# 1. 看看损坏文件长什么样（判断是截断、编码问题还是被外部工具改坏）
Get-Content todos.json.corrupt -TotalCount 20

# 2. 列出可用备份（按时间倒序）
Get-ChildItem .backup\todos.*.json | Sort-Object Name -Descending | Select-Object -First 10

# 3. 若自动恢复选的备份不是你想要的时间点，手动指定
Copy-Item .backup\todos.20261002-142311-482.json todos.json -Force

# 4. 重启服务
```

**若所有备份都损坏**：服务会以空数据启动该类别（其余类别不受影响）。此时唯一的希望是：

- Git 历史（方案 A）：`git log --oneline data/todos.json` 找到最后一个正常版本，`git checkout <commit> -- data/todos.json`
- `.corrupt` 文件本身：如果只是**部分**损坏（如文件尾部被截断），可以用编辑器手动修复——找到最后一个完整的 `}`，补上 `]}` 闭合结构。**修复前先复制一份出来操作**。

### 5.6.2 服务起不来

| 症状 | 原因 | 处理 |
|---|---|---|
| `无法绑定端口 8787` | 端口被占用 | 见 §5.3 端口占用 |
| `静态目录不存在` | `--web=` 路径错，或从别的目录启动 | 用绝对路径，或 `cd` 到仓库根再启动 |
| `package com.google.gson does not exist` | jar 未放置或 classpath 错 | 检查 `server/lib/*.jar`；classpath 分隔符是 `;` 不是 `:` |
| `错误: 无效的目标发行版: 21` | `JAVA_HOME` 指向旧版 JDK | `java -version` 确认；必要时显式指定 JDK 21 的 `javac` 全路径 |
| 编译报 `找不到符号 Math.clamp` | JDK 版本 < 21 | 见 02 §2.6 的替代写法 |
| 控制台中文乱码 | 代码页不是 UTF-8 | 先执行 `chcp 65001` |

### 5.6.3 页面显示"无法连接到本地服务器"

前端明确处理了这个情况（04 §4.6.2 `errorCard`）。原因通常是：

1. 后端没启动 → 运行 `.\server\start.ps1`
2. 后端崩了 → 看控制台最后的异常栈
3. 用了错误的端口 → 检查地址栏端口与启动时打印的是否一致
4. **直接用 `file://` 打开了 HTML** → 必须通过 `http://127.0.0.1:8787` 访问。`file://` 下 ES module 因 CORS 限制无法加载，且 API 请求会失败

### 5.6.4 修改数据文件后页面没变化

`JsonStore` 在**启动时**载入内存，之后以内存为查询源（01 §1.6.2）。外部工具修改数据文件不会被自动感知。

**处理**：重启服务。

这是"内存索引"方案的固有代价。若需要热加载，可加文件监听（`WatchService`）——但会带来"编辑器保存过程中的中间态被读到"的新问题，**不建议实现**。人工编辑数据文件的正确流程是：停服务 → 改文件 → 启服务。

## 5.7 常见问题（FAQ）

**Q：为什么不用 Spring Boot？**
A：Spring Boot 会引入数十个 jar 依赖和 Maven/Gradle 构建链。本项目的 HTTP 需求（十几个 JSON 端点 + 静态资源托管）用 JDK 自带的 `HttpServer` 完全够用，零构建工具即可编译运行。少一层框架意味着少一类问题。

**Q：PowerShell 发中文 JSON 全是问号？**
A：PowerShell 5.1 的 `Invoke-RestMethod -Body <字符串>` 按 ASCII 编码。解决：

```powershell
$bytes = [System.Text.Encoding]::UTF8.GetBytes($jsonString)
Invoke-RestMethod -Uri $url -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes
```

或写入 UTF-8 文件后用 `-InFile`。§5.1 的冒烟脚本已封装成 `PostJson` 函数。

**Q：能多标签页同时打开吗？**
A：能，但有**最后写入胜出**的语义。两个标签页同时编辑同一条记录，后保存的会覆盖先保存的（包括对方的修改）。单用户场景下这是可接受的——你不会真的在两个标签页编辑同一条记录。若将来需要防护，加乐观锁：`Record` 增加 `revision` 整数，PATCH 时带上，服务端不匹配则返回 `409 conflict`。

**Q：为什么金额要用分而不是元？**
A：`0.1 + 0.2 = 0.30000000000000004`。累加金额会产生浮点误差，导致"还差的钱数"出现 `1234.5600000000002`。用 `long` 存分可完全避免。详见 01 §1.5.2。

**Q：可以用手机访问吗？**
A：默认不行——服务只绑定 `127.0.0.1`（02 §2.8），这是刻意的安全默认。若确实需要，改成绑定 `0.0.0.0` 后手机连同网段 WiFi 访问 `http://<电脑IP>:8787`。但请注意：**这会让局域网内任何设备都能读写你的学习记录和心愿单，且没有任何鉴权**。在自己的家庭 WiFi 下勉强可接受，在公共 WiFi（咖啡馆、学校）下绝对不要这么做。

**Q：数据能导入 Obsidian / Notion 吗？**
A：本项目不实现导入导出（00 §0.2.4 的非目标）。但数据是标准 JSON + Markdown 正文，写个几十行的转换脚本即可导出为 Obsidian 的 `.md` 文件（frontmatter 放元信息，正文直接复制）。这是纯 JSON 方案相对数据库方案的一个隐性优势。

**Q：条目多了会变慢吗？**
A：见 01 §1.6.3 的性能预估表。1 万条以内无感知。超过 5 万条时的应对是按年份分片，而非引入数据库。

**Q：为什么饼图不包含"问题已解决率"？**
A：需求原文是"完成/未完成饼图"，四类中只有"要做的事"的完成语义无歧义（ADR-004）。但 `/api/stats/overview` **已经返回了四类的状态分布**，加一个"问题解决率"环只需改前端，不用动后端。

**Q：随机知识点会抽到已掌握的吗？**
A：会，这是刻意的（02 §2.5 `isRandomEligible`）。已掌握的知识仍需复习——这正是"随机回顾"的价值所在。已归档的**灵感**则不会抽出（归档意味着已验证或已放弃）。

**Q：删除的记录能恢复吗？**
A：能，从 `data/.backup/` 找对应时间点的快照覆盖回去（§5.6.1）。这是 ADR-007 选硬删除的前提——没有备份就不该做硬删除。
